# Заявки на товары

## Retail Form

- Поиск показывает товары с нулевым остатком. Их кнопка добавления в корзину отключена.
- Полное совпадение введённого текста с артикулом (включая внутренние пробелы, без учёта регистра и крайних пробелов) оставляет в результатах только этот товар. Если такого артикула нет, сохраняется поиск по нескольким словам. «Поиск всех кл.слов» включён при открытии Retail Form; флажок можно снять для поиска по любому слову.
- Рядом с поиском всегда находится «Создать заявку». Для заявки выбирается строка товара; если результатов нет, используется введённый артикул.
- При отсутствии товара или артикула автоматически открываются сообщение, поле количества и отправка заявки.
- Для существующего товара вручную вводится **недостающее**, а не общее количество.
- Если при редактировании корзины указано 10 шт. при остатке 2 шт., существующее ограничение оставляет в корзине 2 шт., а заявка на 8 шт. сохраняется автоматически. Проверка происходит при завершении ввода количества (потеря фокуса / подтверждение ячейки).
- Успешная автоматическая отправка подтверждается только в MessageBox; постоянный текст на форме не остаётся.
- Повторное подтверждение количества в той же строке корзины обновляет её автоматическую заявку вместо добавления дубля. Новая строка корзины после удаления или оформления заказа создаёт отдельную заявку.
- При ошибке автоматического сохранения доступна повторная отправка. Оформление заказа ожидает успешного сохранения этих заявок.
- Во всех случаях обязателен клиент. Сохраняются дата создания, пользователь, код и имя клиента, артикул, количество и характеристики товара.

## Новые артикулы

Первичное сохранение создаёт черновик, доступный его автору в главном меню, в блоке «Мои новые артикулы».
Автор заполняет наименование, бренд, марку, модель и группу. Альтернативный артикул и примечание необязательны. Цены в форме нет.
Черновик можно сохранить частично; отправка администратору требует заполнения обязательных полей. После отправки черновик исчезает из списка редактирования пользователя.

## Журнал заявок

Путь: **Заявки на товары** в главном левом меню, сразу под «Инвентарь». Из «Администрации» пункт удалён.
Видимость пункта и доступ к журналу защищены отдельным правом **«Заявки на товары»** (`ProductRequests`). Право `Admin` для этого раздела не требуется и само по себе не предоставляет доступ.
Новое право автоматически появляется в списке прав после запуска обновлённого приложения; его необходимо включить в настройках нужной роли. Назначения существующих ролей автоматически не расширяются.

| Раздел | Содержимое | Действия |
| --- | --- | --- |
| Недостаточный остаток | Существующие товары, которых не хватило | Печать, удаление |
| Нет в наличии | Товары с нулевым остатком при создании заявки | Печать, удаление |
| Новые артикулы | Отправленные пользователями новые артикулы | Печать, галочка «Обработано» |

В каждом разделе доступны бренд и период; пустые даты означают отсутствие ограничения. Конечная дата включается целиком.
Кнопка «Применить / обновить» загружает данные по выбранным фильтрам. Одинаковые артикулы объединяются, количество суммируется **после фильтрации**.
«Детальный просмотр» открывает все вошедшие в строку заявки с клиентами, пользователями, датами и характеристиками.
Удаление и отметка обработки затрагивают только заявки, включённые в отображаемую строку по применённым фильтрам.
Обработанные новые артикулы скрыты по умолчанию; их можно показать флажком «Показывать обработанные», применить фильтры и при необходимости снять отметку.
Печать выводит весь отфильтрованный список с итоговым количеством, включая строки за пределами экрана, на необходимом числе страниц.

## База данных и обновление

Миграция `20261102000000_AddProductRequests` создаёт таблицу `ProductRequests` и триггер `TR_Products_RemoveNewArticleRequests`.
Она применяется существующим механизмом миграций при запуске обновлённого приложения.
История хранит снимки пользователя, клиента и характеристик товара. Артикул заявки не является внешним ключом: он может отсутствовать в справочнике товаров.
При добавлении или изменении артикула в `Products` триггер удаляет **все** соответствующие заявки типа «Новые артикулы», включая черновики и обработанные записи. Другие типы заявок сохраняются.
Модель EF настроена для работы с триггером SQL Server без несовместимого `OUTPUT`.

## Проверки

```powershell
dotnet build PresentationWpf/PresentationWpf.csproj --no-restore
dotnet run --project tests/ProductRequests.Tests/ProductRequests.Tests.csproj
dotnet run --project tests/PaymentInput.Tests/PaymentInput.Tests.csproj -- --product-requests
```

Первый набор проверяет модель и миграцию, сохранение и повторную отправку, отдельное право доступа к журналу, владельца черновика, фильтры, обработку, удаление и триггер. Он создаёт отдельную LocalDB-базу со случайным именем, хранит её файлы в каталоге результатов тестов и удаляет её после проверки. Рабочая база приложения не используется.
Параметр `--no-database` запускает только проверки количества, суммирования и соответствия модели снимку миграции.
Второй набор загружает настоящие WPF-формы без запуска приложения и его миграций, проверяет элементы и привязки, рендерит формы в каталог результатов тестов и проверяет многостраничную печать.
