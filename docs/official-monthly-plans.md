# Месячные планы официальных клиентов

Раздел «Месячные планы» находится в левом меню под «Клиенты». Период выбирается отдельно: месяц и год.

Во вкладке «Настройка планов» показаны все клиенты с существующей галочкой `OfficialCustomer`. Пустая сумма означает отсутствие плана за выбранный месяц. Введите положительные суммы нужным клиентам, затем нажмите общую кнопку «Сохранить» справа от «Показать». Все изменённые планы сохраняются одной операцией: при ошибке ни одна сумма не записывается. Неизменённые строки, включая клиентов без плана, пропускаются. Суммы поддерживают дробную часть с точкой или запятой. Изменение суммы не затрагивает другие месяцы и не меняет статус клиента.

При первом обращении к новому месяцу недостающие планы автоматически создаются по последнему сохранённому плану каждого официального клиента из предыдущих месяцев. Переносится полная сумма плана; продажи и остатки прошлого месяца не переносятся. Это работает при открытии настроек, контроля, панели заказов и при сохранении нового официального заказа, поэтому продавцу не требуется ждать действий администратора. Уже заданные суммы месяца не перезаписываются. Клиенты, которым план никогда не задавался, остаются без плана. Достаточно изменить нужные суммы и нажать «Сохранить». Одновременное открытие месяца в нескольких экземплярах не создаёт дубликатов. История сохраняется отдельно по месяцам.

Во вкладке «Контроль выполнения» показаны официальные клиенты с установленным планом, включая выполнивших его. Фильтр «Клиент» позволяет выбрать одного клиента или «Все клиенты»; итоги считаются по показанным строкам. Отображаются план, «Продажа», остаток и общие итоги. Остаток равен `max(0, план − покупки)`, если эта сумма выше порога обычного заказа; иначе показывается 0. Общий остаток — сумма этих индивидуальных остатков с учётом порога.

Покупки рассчитываются по деталям заказов (`Price × Quentity`) с существующим `OfficialOrder = true` и датой заказа внутри календарного месяца. Обычные заказы не учитываются. Заказы и статус клиента задним числом не меняются. При установке плана учитываются уже существующие официальные заказы этого месяца.

В «Настройке планов» есть «Порог обычного заказа» — одна общая сумма для всех клиентов и месяцев. Она сохраняется общей кнопкой «Сохранить», отдельно либо одновременно с изменёнными планами. Допускается ноль и положительные суммы с двумя знаками после запятой; начальное значение — 0. Право управления планами требуется также для изменения порога. Несохранённый ввод сохраняется при фоновом обновлении. Если одна из сумм неверна, ни порог, ни планы не записываются.

Если остаток клиента меньше или равен порогу, новый заказ автоматически становится обычным (`OfficialOrder = false`) и ограничение по плану к нему не применяется. Например, порог 5 и фактический остаток 3 или ровно 5 означают обычный заказ. В контроле выполнения и на панели заказов такой остаток показывается как 0 и не входит в общий остаток. Суммы плана и официальных продаж сохраняются без изменений. При уменьшении порога фактический остаток снова отображается, если он выше нового порога.

Если остаток выше порога, сумма официального заказа не может превышать его. После существующих финансовых проверок корзина уменьшает количество в изменённой строке до допустимого; при обновлении остатка сначала уменьшаются последние строки. Показывается сообщение с просьбой оформить остальные товары отдельным заказом. Проверка применяется также к изменениям цен и работает независимо от прав на отображение плана и права продажи сверх кредитного лимита. Перед сохранением проверяется свежий остаток, а сервис повторяет проверку в транзакции: одновременная продажа у другого продавца не позволяет превысить план. При достижении плана следующие заказы становятся обычными.

Возврат по накладной уменьшает покупки в месяце исходного официального заказа, даже если оформлен позже. Ручные возвраты без связи с официальной накладной не учитываются. Расчёт использует текущие записи заказов и возвратов, а не накопленный счётчик, поэтому изменение, удаление заказа или возврата влияет на результат при следующем обновлении. Покупки по отдельному заказу после возвратов не опускаются ниже нуля.

В заказах общий показатель находится в одной строке справа от «Маршрут». Он не зависит от выбранного клиента и не очищается при переключении клиентов. Индивидуальный показатель находится справа от «Бартер» и появляется только для выбранного официального клиента с планом. Галочка ОЗ убрана из формы: для нового заказа используется автоматический `OfficialOrder`. Для официального клиента без плана сохраняется прежнее значение по умолчанию — официальный заказ.

После сохранения заказа, возврата, плана и изменения данных клиента открытые показатели обновляются. Дополнительно выполняется обновление раз в минуту, в том числе для изменений из другого экземпляра программы и смены календарного месяца. Перед сохранением заказа план проверяется заново. Одновременные официальные заказы одного клиента проверяются последовательно в транзакциях SQL Server. Несохранённый ввод сумм в настройке сохраняется при фоновом обновлении текущего месяца.

Четыре независимых права назначаются роли в существующей форме прав:

| Право | Назначение |
| --- | --- |
| `OfficialMonthlyPlans.Manage` | Настройка сумм планов официальных клиентов |
| `OfficialMonthlyPlans.View` | Подробная таблица контроля и история месяцев |
| `OfficialMonthlyPlans.RetailTotal` | Общий остаток справа от «Маршрут» в заказах |
| `OfficialMonthlyPlans.RetailIndividual` | Остаток выбранного клиента в заказах |

Для работы с оформлением заказов также необходимо прежнее право `Orders`. Отсутствие прав на отображение не меняет автоматическое правило `OfficialOrder`. Новые права добавляются в каталог при запуске, но автоматически существующим ролям не назначаются.

Таблица `OfficialMonthlyPlans` содержит ключ `(CustomerId, Month)` и сумму `Amount`. `Month` хранится как первое число месяца. Общий порог хранится в единственной строке `OfficialMonthlyPlanSettings` (`Id = 1`, `NonOfficialThreshold`). Новые поля статуса клиента и заказа не создаются. Миграции `20261110000000_AddOfficialMonthlyPlans` и `20261110010000_AddOfficialMonthlyPlanSettings` применяются существующим механизмом запуска приложения. Рабочая база не требуется для автоматических проверок: интеграционные проверки создают отдельную временную LocalDB и удаляют её после завершения.
